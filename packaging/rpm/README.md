# RPM repository layout

This directory is the source of truth for Splitlane's RPM repository. **No
such repository is published yet**: Splitlane has no package host, and
`.github/workflows/repo_publish.yml` stays disabled until one exists. Until
then, install the `.rpm` from a GitHub release.

Nothing here is populated in git - the publish workflow copies built `.rpm`
artifacts into `Packages/` and runs `createrepo_c` against this tree.

## Layout

```
packaging/rpm/
├── Packages/                  # ← .rpm files land here at publish time
│   └── splitlane-<version>-1.x86_64.rpm
└── repodata/                  # ← generated by createrepo_c, not committed
    ├── repomd.xml
    ├── repomd.xml.asc         # ← GPG detached signature of the metadata
    ├── primary.xml.gz
    ├── filelists.xml.gz
    └── other.xml.gz
```

## Client `.repo` config

Once a host exists, a user adds this to `/etc/yum.repos.d/splitlane.repo`
(`<package-host>` stands for that host):

```ini
[splitlane]
name=Splitlane
baseurl=https://<package-host>/rpm
enabled=1
gpgcheck=1
repo_gpgcheck=1
gpgkey=https://<package-host>/gpg
```

- `gpgcheck=1` - verifies each RPM's embedded signature (added by
  `rpmsign --addsign` in `release.yml`).
- `repo_gpgcheck=1` - verifies the `repomd.xml.asc` signature on the
  repository metadata before trusting any listed package.

## Pruning

Old RPM files accumulate in `Packages/` across publishes. There is no
retention policy yet; prune the bucket by hand if storage grows unbounded.
